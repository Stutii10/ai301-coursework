# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-scope-fidelity | The diff's changed files and hunks, read against plan.md's Scope, Files, Changes, and ## Deviations | Every changed file, or its folder, is named in the plan or in Deviations, and nothing the plan promises is silently missing. Fails on a file or change the plan never names (silent drift, unrelated cleanup). A change not in the plan that Deviations records with a reason passes. | required |
| description-matches-diff | The description's claims (summary, any Changes list, "exactly / no X added" statements), read against the diff | Each claim about what the change does (behavior, files, options, scope) is shown by a line in the diff, and each change in the diff is mentioned in the description (as a Changes bullet if the template has a Changes section). Tests and helpers that serve a described change are covered by it. Read claims for substance: a case exercised inside a combined test meets a "tests cover X" claim. A negative claim ("no options added") passes if nothing in the diff adds it. Pasted output is graded under test-evidence-real, not here. Fails if the description claims a behavior, file, or option the diff doesn't deliver, or leaves out a change in behavior or scope that the diff makes. | required |
| tests-cover-test-plan | The plan's test plan, read against the test files in the diff (or the commands the test plan names, if no test file is expected) | For each case the plan's test plan names, including controls and edge cases, the diff adds or changes a test, or the evidence runs the named command. A control the test plan expects to stay unchanged is covered when the evidence reports it checked with its result. Fails if a named case has neither, or is never mentioned. A gap that the description and Deviations both disclose passes as disclosed. | required |
| test-evidence-real | The test evidence section and the description's Testing section, read against the test plan and the repo's required checks | Pass if (a) every behavior the fix changes, as the test plan names it (the repro, each named failure mode), is shown run on the branch: the command or inputs, and the specific observed result (printed output, exit code, returned values, exact message text), before and after where the test plan expects a change. A specific result noted beside the command that produced it (`# after: exit 0, no error`) counts; for interactive or visual behavior, a step-by-step transcript naming the inputs and the exact result seen counts, in any notation (arrows or keystroke steps are fine); judge whether the inputs and exact observed text are named, not whether it looks like a terminal paste. And (b) every control the test plan expects unchanged, and every other check the plan or the repo's template lists, is reported as run, with its result. For controls and routine checks (full suite, lint, format, typecheck), a stated result naming the control, command, or count, like "cargo test -p nu-protocol passes (312 tests)", is enough unless the diff or other evidence contradicts it. Fail if a changed behavior is only asserted ("works now", "verified locally", "tests pass" with nothing named), if the repro or a named failure mode is never run, if the evidence runs something other than what the test plan names (a control in place of the repro, an unchanged code path), if the result shows the bug still present, if a failure is hidden or summarized away, or if a required check is never mentioned. Message wording that depends on code outside the diff is not a contradiction. A check that failed and is reported with its reason passes. A shortfall disclosed in the description and Deviations passes as disclosed. | required |
| checklist-ticks-true | Any ticked boxes or checklist claims in the description, read against the diff and the pasted output | Every ticked box or checklist claim is backed. A claim that something was added (changelog, test, docs, translation string) needs the file in the diff. A claim that a routine step was run (formatter, generator with no diff, lint) is backed by a stated result, as in test-evidence-real, unless the diff contradicts it. The CI box is left unticked. Fails on a tick with no proof, such as "changelog added" with no changelog file in the diff. Passes if the description has no checklist. | required |
| diff-reviewable | The diff's hunks and file list, and the description | No debug lines, commented-out code, unrelated edits, formatting churn, or planning files (plan.md, pr_draft.md, test_evidence.md, comment.md) in the diff. A reviewer can tell what changed and why from the description. Fails on debris or a diff the description doesn't let a reviewer follow. | required |
| repo-standards-met | The repo's PR template, CONTRIBUTING and stated AI policy (repo-facts block in eval mode), read against the description and the branch name | Every asked-for section is filled with real content, not boilerplate. The issue is referenced (Closes #N with the right number) wherever the template or contribution docs ask. An AI-use disclosure is present wherever the repo's template or policy asks for one, and always in live mode (the course requires it, under Notes for Reviewers). In live mode the branch name has a type prefix, the issue number, and a short description. Fails if any stated ask is skipped. If the repo states no asks, nothing can fail here. | required |

## Verdict rule

Accept only if every required check passes. Reject if any required check fails or is unclear. Unclear means the evidence is missing or ambiguous, and it counts as a fail. Preferred checks never change the verdict. A shortfall that the description and plan.md's Deviations honestly disclose is graded as disclosed, not as drift. A change that exists only in the diff is drift.
